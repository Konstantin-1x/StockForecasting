# Проверки для раздела тестирования

Этот файл нужен как рабочий чек-лист: по нему можно запустить автоматические тесты и получить изображения для вставки в раздел ВКР о тестировании и развертывании.

## 1. Автоматические JUnit-тесты

Запуск только демонстрационных тестов для отчета:

```powershell
.\gradlew.bat test --tests "*Diploma*" --no-daemon --console=plain
```

Запуск всех тестов проекта:

```powershell
.\gradlew.bat test --no-daemon --console=plain
```

После выполнения результаты находятся в:

```text
build/reports/tests/test/index.html
```

Для отчета удобно открыть этот HTML-файл в браузере и сделать 1-2 снимка:

- общий результат прохождения тестов;
- раскрытый список тестов `DiplomaDataCollectionReliabilityTest` и `DiplomaWebInterfaceTest`.

Рекомендуемые подписи:

- Рисунок 3.X – Результат выполнения автоматических тестов приложения.
- Рисунок 3.X – Проверка сценариев сбора данных и работы пользовательского интерфейса.

## 2. Что проверяют добавленные тесты

`DiplomaDataCollectionReliabilityTest` проверяет слой сбора данных:

- получение демонстрационного JSON-каталога по HTTP-запросу и извлечение товаров с вознаграждением за отзыв;
- временное исключение неработающего прокси-сервера из пула и его возврат после успешного соединения.

`DiplomaForecastLayerTest` проверяет слой прогнозирования:

- обучение MLP-модели на демонстрационной выборке промо-показателей;
- расчет трех целевых параметров: ставки за отзыв, срока кампании и ожидаемого остатка товара;
- вывод метрики ошибки и интерпретируемого прогноза для товара продавца.

`DiplomaWebInterfaceTest` проверяет веб-слой:

- перенаправление неавторизованного пользователя со страниц администратора и продавца на страницу входа;
- вход администратора и загрузку административной панели;
- вход продавца, открытие страницы товаров, добавление товара, открытие страницы прогнозирования и отправку запроса на расчет прогноза.

Связь с текстом раздела 3.3:

| Фрагмент раздела | Автоматическая проверка | Что можно показать в отчете |
| --- | --- | --- |
| Проверка подсистемы сбора данных | `DiplomaDataCollectionReliabilityTest` | HTML-отчет Gradle со статусом PASSED по получению JSON-каталога, извлечению товаров с вознаграждением и проверке прокси-пула |
| Проверка слоя прогнозирования | `DiplomaForecastLayerTest` | Консольный вывод Gradle с архитектурой MLP, размером обучающей выборки, метрикой ошибки и прогнозом |
| Проверка авторизации и разграничения доступа | `DiplomaWebInterfaceTest` | HTML-отчет Gradle по перенаправлению неавторизованного пользователя и входу администратора |
| Проверка пользовательского сценария продавца | `DiplomaWebInterfaceTest` | HTML-отчет Gradle по добавлению товара и запуску расчета прогноза |
| Проверка времени отклика веб-интерфейса | `tools/capture-report-screenshots.mjs` | `07-frontend-timings.png` и `frontend-timings.json` |
| Проверка обработки неправильной ссылки | `tools/capture-report-screenshots.mjs` | `08-not-found-page.png` |

## 3. Автоматическое получение снимков веб-интерфейса

Сначала запустите приложение локально или через Docker, чтобы был доступен адрес:

```text
http://localhost:8080
```

Затем выполните:

```powershell
node .\tools\capture-report-screenshots.mjs http://localhost:8080
```

На успешном запуске сценарий выводит только контрольные строки с `[OK]`: какая страница проверяется, какой HTTP-статус получен, сколько миллисекунд заняла загрузка и в какой файл сохранен снимок.

Снимки будут сохранены в:

```text
outputs/testing
```

Будут сформированы следующие файлы:

- `01-start-page.png` – стартовая страница;
- `02-login-page.png` – форма входа;
- `03-admin-dashboard.png` – административная панель;
- `04-seller-products.png` – страница товаров продавца;
- `05-seller-product-form.png` – форма добавления товара;
- `06-seller-forecasts.png` – страница прогнозирования продавца;
- `07-frontend-timings.png` – таблица времени отклика страниц;
- `08-not-found-page.png` – страница неправильной ссылки.

Дополнительно создается файл:

```text
outputs/testing/frontend-timings.json
```

Его можно использовать как источник численных значений времени отклика.

## 5. Если браузерный сценарий не запускается

Проверьте, что:

- приложение действительно открывается по адресу `http://localhost:8080`;
- в системе установлен Node.js;
- в проекте доступен пакет Playwright.

Если Playwright отсутствует, установите его командой:

```powershell
npm install playwright
```

После этого повторите запуск сценария получения снимков.
